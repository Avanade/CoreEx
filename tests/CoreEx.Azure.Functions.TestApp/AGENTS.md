# Functions executable test host

This non-packable net10.0 host demonstrates native HTTP, HTTP idempotency, Service Bus, Blob, and Timer integration for framework tests. It is not a Contoso business domain. Read the [Functions package guide](../../src/CoreEx.Azure.Functions/README.md) and scoped Functions/test instructions before modifying it.

## Inventory file capability

[InventoryImports](InventoryImports/README.md#example-matrix) contains six generation-first examples: independent units and complex parent/child units with header/trailer metadata for each of CSV, JSON, and JSONL. The six checked-in `inventory*-file.yaml` definitions live in `tests/CoreEx.Azure.Functions.TestApp.CodeGen`; each owns a separate output folder under `InventoryImports`. File CodeGen generates the wire models, mappings, validators, contexts, processors, and create-only handlers. Keep application execution in handlers and trusted context/report/EOF hooks in handwritten processor partials. The generated processor's protected `Services` property exposes its construction-time provider for coordinator dependencies; unit business services resolve through the handler's fresh child scope.

Native input routes are `inventory-adjustments/{name}`, `inventory-json/{name}`, `inventory-jsonl/{name}`, `inventory-csv-batch/{name}`, `inventory-json-batch/{name}`, and `inventory-jsonl-batch/{name}`, all with connection `ImportStorage`. Their function names and payloads are listed in the example matrix. The Blob SDK adapter pins both processor passes to the selected ETag; reports are written through `AppendBlobClient` with outcome metadata, not local files. Complex handlers sum bin lines into one parent adjustment; bin-level stock is not persisted. Pass-local totals reconcile against the trailer at EOF before replay. The supported SQL Server unit of work atomically commits each parent inventory update, durable receipt, and outbox write. Pre-provision schema/business data, input containers, report storage, and Event Grid subscriptions outside invocation execution.

Content rejection and application failures follow explicit report/trigger policies; operational failures and cancellation propagate. Earlier business units may commit before a later unit fails, so durable receipt deduplication is required for safe retries; this is not exactly-once delivery.

The local immutable snapshot helper supports stream-factory tests only; there is no database/report provisioning CLI. `InventoryImportTests` includes invocation/component tests for all six examples with recording application/report boundaries. The existing Aspire Functions AppHost runs Azurite, SQL Server, and Core Tools; its runtime cases cover all six input routes. They upload real input, then use `EventGridExtensionMethods.CreateBlobCreatedEvent` and `FunctionsWebhook(...).PostBlobCreatedAsync(...)` to simulate notification delivery; Azurite itself does not emit Event Grid events. The binding, SDK operations, database transaction, and report writes are real in the harness, but Azure Event Grid provisioning/authentication/delivery are not proven. Do not claim runtime tests passed until they have been run.
