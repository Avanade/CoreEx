# CoreEx.Azure.Storage.Blobs — AI Usage Guide

Host-neutral revision-pinned Blob input and streamed JSONL/CSV attempt reports, independently consumable from `CoreEx.IO` and Functions. Reference this package where the host/storage adapter lives; do not add Azure SDKs to `CoreEx.IO` or business contracts.

Use `await BlobReadSource.CreateAsync(blob, cancellationToken)` once per invocation. Construct `FileProcessingIdentity` yourself from the definition/version, `source.SourceUri.AbsoluteUri`, attempt ID and `source.ETag.ToString()`. Pass `source.OpenReadAsync` as the processor's fresh-stream factory. All reads carry `IfMatch`; callers/processors dispose returned streams. `ContentLength` supports caller-owned admission. Source URIs exclude SAS/user information and preserve only version/snapshot query selectors. An ETag is not historical storage: select a version/snapshot-specific client explicitly when needed; replacement/deletion failures propagate.

Use `BlobJsonlReport.CreateName(definition, version, credentialFreeSource, revision, attemptId)` for bounded attempt names and `new BlobJsonlReport(appendBlobClient, serializerOptions)` for reporting. Provision the container separately. Await `StartAsync`, sequential `WriteAsync(record)` calls, and `CompleteAsync(terminalRecord, outcome)`. Start never overwrites an existing Blob; metadata starts at InProgress, and completion writes its terminal record before final metadata. Records are compact UTF-8 JSONL. Diagnostics/summary record shapes, terminal outcome meanings, limits and sensitive-data policy belong to the caller.

For flat business-facing reports use `BlobCsvReport.CreateName(...)` and `new BlobCsvReport(appendBlobClient, columns, formulaHandling)`. Columns are explicit, copied, nonempty and ordinally distinct. StartAsync creates the Blob and awaits one header; WriteAsync accepts an explicitly ordered `IReadOnlyList<object?>` with exactly that width. Null/string/scalar IFormattable/IConvertible cells format invariantly; project complex objects yourself and preformat schema-specific values. UTF-8 without BOM, comma separation, CRLF records and correct quote/newline escaping are fixed. CompleteAsync(outcome) sets metadata only, never inserts a summary row. JSONL remains the default for mixed lifecycle records.

Require an explicit `CsvFormulaHandling` choice: Reject, PrefixApostrophe (deliberately changes text), or Preserve (accepts spreadsheet interpretation risks). Detection includes leading tab/CR/LF and =, +, - or @ after whitespace, including negative numbers and headers; CSV quoting alone is not protection, and this policy is not a universal spreadsheet-safety guarantee. Schema/formatting failure faults the report without a partial row. Both report types share conditional append/lifecycle mechanics; do not build a parallel retry or overwrite path.

Writes use ETag/append-position conditions and propagate failures. After a failure the instance is faulted; create a distinct attempt, not a blind retry. SDK retries remain caller-configured and can encounter an already-committed append or finalization with a lost acknowledgement. Report streaming is not exactly-once reporting or business deduplication. No automatic finalization, container creation, archival, deletion, snapshot creation, quotas or background listeners. Do not copy these helpers into consumer projects or claim Blob-to-broker sends are transactional.
