 # Change log

Represents the **NuGet** versions.

## v4.4.0 (Unreleased)
- *Enhancement:* Added native payload publishing through the existing `IEventPublisher`, independently of event/command intent and destination routing. `EventData.CreateNative()`, `CreateNativeWith<T>()`, `CreateNativeWithData(BinaryData)` and `.AsNative()` support JSON or byte-exact opaque payloads through direct publishing and SQL Server, PostgreSQL and Cosmos transactional outboxes. Internal CloudEvents preserve versioned native metadata; final Service Bus delivery sends only the payload, without a CloudEvent envelope or CE-prefixed headers. Native messages bypass automatic payload filtering, including default ETag exclusion; opaque bytes retain Base64 internal storage where required.
  - Native Subject defaults to formatted `EventData.Title`; `EventFormatter.IncludeNativeSubject = false` omits it. The resolved Subject is persisted and retained through reconstruction, independent of relay formatter settings. Existing publishable `EventData.Attributes` become unprefixed native string application properties; underscore-prefixed/null entries are omitted, and framework/control metadata is not implicitly exported. No separate native options/header dictionary or CLR scalar-type preservation is introduced.
  - Added optional `EventData.CorrelationId` and `CausationId`, mapped through configurable `EventFormatter.CorrelationIdAttributeName`/`CausationIdAttributeName` using the existing extension-attribute conventions. Standard `correlationid` maps to Service Bus CorrelationId for both representations, including when optional CE attributes are excluded; causation remains optional CE metadata. Correlation and causation identifiers are application-supplied and independent of the existing distributed-tracing metadata.
  - Added synchronous `ServiceBusPublisher.ConfigureMessage` customization for final broker messages, including typed application properties and exceptional Subject overrides. All messages are prepared before sending; batch overflow and send retries do not rerun preparation, while a new publish attempt/redelivery can. Configure the final sending host for outbox delivery; callbacks are not persisted.
- *Fixed:* CloudEvent payload conversion now preserves explicit JSON null, complete media types and JSON token content, decodes text without extra JSON quoting, and restores Base64 payloads as `BinaryData`. Non-JSON payloads use Base64 internal encoding; binary encoding validates required CE metadata.
- *Fixed:* Service Bus CloudEvent binding now preserves required binary metadata when optional attributes are excluded, recognizes structured JSON content types with parameters, rejects unsupported binary spec versions, and avoids inventing occurrence timestamps. Structured bodies remain authoritative; binary broker identity/content fields take precedence over duplicate attributes, with broker CorrelationId used only when the CE correlation extension is absent.
- *Documentation:* Updated publishing, host and relay-test guidance and assertion helpers for native delivery, persistence, rollback and mixed native/CloudEvent batches. Prefer CloudEvents for CoreEx `SubscribedManager`/`[Subscribe]` consumers: binary CloudEvents already provide a payload-only body while retaining dispatch metadata. Native selection requires a concrete incompatible receiver contract and a native-compatible consumer.
- *Upgrade:* Upgrade every final publisher/relay before enabling native writes; older versions can emit the internal CloudEvent externally. Drain or quarantine native backlog before rollback. No outbox schema migration is required; existing atomicity, at-least-once delivery and session policies remain unchanged.

## v4.3.0
- *Maintenance:* Split CI into isolated core, per-framework sample, sample Aspire E2E, Functions runtime, and template jobs, with merged coverage and a final required-success gate. The checkout E2E test now waits for the active Product to replicate to Shopping before adding it to a Basket, with bounded polling and an actionable timeout instead of a timing assumption.
- *Enhancement:* Added opt-in subscriber payload cleanup via `EventSubscriberBase.AutoCleanValue` (default false) and nullable per-handler/message-type `SubscribedBase.AutoCleanValue` overrides. CloudEvent payloads and native JSON `ServiceBusSubscriberBase<TValue>` bodies use WebApi-equivalent cleaning before required checks, validation and handling, without root/nested object collapse or modifications to serialized messages, keys or metadata. Unlike WebApi request cleanup, this defaults off because published events are generally canonical already and cleanup is typically redundant. Cleanup failures retain normal receive error handling; retry/settlement policies are unchanged.
- *Enhancement:* Added `CoreEx.IO`, a host-neutral, stream-based CSV processing runtime for bounded asynchronous input, flat and hierarchical files, typed mapping and validation, streamed diagnostics, validate-before-execute processing, and report-only processing of fully validated units with explicit partial outcomes. Flat named mappings optionally enforce exact headers and row widths. `CoreEx.CodeGen` supports `*-file.yaml` definitions and generates typed records, mappings, validators, contexts, processors, and handler starters for flat, hierarchical, and unordered routed files. Azure Functions and Blob Storage remain host-owned integrations rather than runtime dependencies.
- *Enhancement:* Added Azure Functions isolated-worker host support (`CoreEx.Azure.Functions`) with scoped CoreEx execution context, HTTP `WebApi` integration including explicit idempotency/replay support, and explicit Service Bus settlement for CloudEvent and typed native JSON subscribers. Includes native Blob/Event Grid integration examples and UnitTestEx invocation/Aspire runtime proofs, preserving Functions-owned trigger and retry behavior.
  - Added `coreex-functions`, a minimal Azure Functions isolated-worker host template with CoreEx execution context and a matching UnitTestEx test project. Supports shared Application/Infrastructure layers (default), self-contained integrations via `--shared-core false`, and multiple independently named Function Apps.
  - Added optional `--test-common-project` support to explicitly reference a shared test library independently of host/shared-library naming; a supplied missing project fails the build.
  - Added the `coreex-functions` AI skill, Copilot/Claude wrappers, scoped Functions instructions and package guide to the version-pinned AI bundle. Covers native HTTP/Service Bus/Blob/Timer capabilities, meaningful invocation tests, shared-core/standalone processing, and explicit runtime verification boundaries.
- *Enhancement:* Added `coreex-solution` for standalone repository scaffolding: `.slnx`, centralized package/build conventions, root guidance and lightweight Test.Common by default (`--test-common false` opts out), without mandatory business layers or database/broker setup. The scaffold workflow stages existing-project retrofits and explicitly wires test references while preserving existing package versions, aliases and host implementation.
- *Enhancement:* Added independent `coreex-codegen` design-time console scaffolding without database/reference-data prerequisites or runtime-project references. File definitions target existing runtime projects; use explicit `file` commands from the console directory. RefData remains the default command, and no dummy definitions are generated.
- *Behavior change:* `coreex-functions` now follows effective Central Package Management independently of `shared-core`, using inline pinned versions only when CPM is disabled instead of forcing standalone projects to opt out. Standalone hosts added beneath an existing CPM root require corresponding central package versions; existing project-local opt-outs remain supported.
- *Behavior change:* `Result.ThrowOnError()`, `Result<T>.ThrowOnError()` and failed result value access now preserve the original exception instance, type and existing stack trace instead of wrapping previously thrown errors in a new `AggregateException`. Consumers catching the former wrapper must catch the underlying exception instead; explicitly aggregated errors remain unchanged.
- *Behavior change:* Ambient event baggage capture and incoming baggage propagation are now opt-in. Set `EventFormatter.CaptureBaggage = true` when publishing and `EventSubscriberBase.PropagateBaggage = true` when receiving (or `FunctionsServiceBusReceiveArgs.PropagateBaggage = true` for a native Functions callback) where trusted baggage propagation is required. Incoming baggage is bounded; trace-context linking remains automatic and independent of baggage.
- *Behavior change:* `ServiceBusPublisher` now translates only classifier-confirmed transient `ServiceBusException` failures at the publication boundary into generic CoreEx `TransientException` failures, after configured send retries, preserving the final broker exception as `InnerException` and enabling logging. Batch-creation failures use the same classification but are outside send retries. Permanent failures and caller cancellation remain unchanged. CoreEx WebApi defaults to HTTP 503 with `Retry-After: 90`; callers catching transient SDK exceptions must now catch `TransientException`. Acceptance may be partial or unconfirmed, so retries still require application-level idempotency; committed outbox-backed API requests remain successful.
- *Enhancement:* Added opt-in `WithAccept()` as an immediate operation guard against the effective generated JSON media type, shared by MVC and Minimal WebApi. Supports standard wildcards, media parameters, quality exclusions, and copied/keyed instance defaults; rejects incompatible requests with 406 and malformed headers with 400, preserving error rendering and existing Vary values. Set response overrides before the guard and call it before business execution; no negotiation or automatic enforcement is introduced.
- *Enhancement:* Added instance `WebApiBase.DefaultJsonMediaType` and per-operation `WithContentType(...)` for generated JSON responses, including option-copy support and MVC/Minimal parity. Defaults remain `application/json`; explicit results and error representations are unaffected.
- *Enhancement:* Added protected `CreateResultForException(HttpContext, Exception, IExtendedException?)` hooks to MVC and Minimal WebApi, preserving default ProblemDetails rendering while keeping classification, logging, propagation, and applicable Retry-After headers outside overrides. Renderer failures propagate without re-entry; keyed DI examples demonstrate independent serializer, success-media-type, and error configuration without protocol-specific dependencies.
- *Behavior change:* Minimal WebApi now propagates unexpected failures carried by `Result`/`Result<T>` when `ConvertUnhandledExceptionsToProblemDetails` is `false`, matching MVC and thrown exceptions. Explicitly enable the flag to convert these failures inside WebApi. Returned own-operation-token cancellation now propagates consistently with thrown cancellation, and generated 204/304 responses no longer carry JSON bodies even when a value is supplied.
- *Enhancement:* Added per-call `Action<ValidationException>` configuration overloads to `Validator<TEntity>.ValidateAndThrowAsync` and `ValidateWithResultAsync`, including convenience overloads without `ValidationArgs` and support through `IValidatorEx<T>`/`ValidatorBase` for throwing validation. Configuration runs once only on validation failure and is never retained on shared validators. Configured overloads require an explicit cancellation token; convenience overloads reject null actions. Existing positional `(value, null, cancellationToken)` and `(value, null, default)` calls are now ambiguous: use `args: null` to select the original overload.
- *Enhancement:* Added `IValidationResult.ThrowOnError(Action<ValidationException>)` with a default interface implementation for existing implementers, plus fluent overloads on `ValidationContext<TEntity>` and `MultiValidatorResult`. The non-null action runs once only for a validation exception; success returns the same result and other exception types retain their identity and existing stack trace.
- *Fixed:* Fixed and improved AI skills, instructions, guidance and generated templates.
- *Fixed:* Object cleanup now writes non-default cleaned strings and `DateTime` values back to writable properties on generated contracts and reflection-backed POCOs, including `DateTime.Kind` changes. Preserves cleanup exclusions, read-only properties, nested graph identity, wrapped values and existing `CleanAndDefault` semantics; `[String]` setters are not required for ordinary object cleanup.
- *Behavior change:* Upgraded `UnitTestEx` (including `UnitTestEx.NUnit`, `UnitTestEx.Aspire`, and `UnitTestEx.Azure.Functions`) to v6.1.0 across the central package catalog and generated template pins, a major version upgrade from 5.x that flows transitively to consumers of `CoreEx.UnitTesting`. The `WithAspireTester<TAppHost>` class has been removed from `CoreEx.UnitTesting` as it is now provided by `UnitTestEx` (same `UnitTestEx` namespace and behavior); no code change is expected beyond updating to the new package versions, but consumers pinning `UnitTestEx` 5.x must upgrade.
- *Maintenance:* Updated `OnRamp` to 2.3.1 and the corresponding `CoreEx.Template` `UnitTestEx` dependencies.

## v4.2.0
- *Enhancement:* Added `Optional<T>` for explicit request/patch DTOs to distinguish omitted fields from supplied null/default values, with JSON conversion, contract cleaning and generated reference-data support, and inner-type OpenAPI schemas. Validation uses `.Unwrap()` for supplied values and `.Specified()` to require presence; only specified fields should be mapped into ordinary application/domain models. Custom value wrappers (optional or always present) can independently opt into runtime cleaning through the public `IWrappedValueCleaner<TSelf>` capability, with cached constrained dispatch avoiding wrapper boxing on typed cleaning paths.
- *Enhancement:* Added expression-based `MessageItem.CreateErrorMessage<TEntity>` factories for aggregating field errors, with inferred friendly invalid messages and optional JSON naming options. Validation exception factories share this message construction; policy guidance now distinguishes known request-contract expressions from explicit paths in reusable policies.
- *Enhancement:* Added single-use fluent HTTP request builders with `Get`/`Post`/`Put`/`Patch`/`Delete` shortcuts, `WithJson` for JSON bodies and `WithContent` for explicit HTTP content (also available on `HttpRequestMessage`). Exactly one body assignment is permitted; repeated execution, configuration after execution starts, and conflicting body assignments throw `InvalidOperationException`. PATCH does not imply JSON Merge Patch.
- *Enhancement:* Added `WithStatusResult` / `WithErrorStatus` to HTTP request builders, including validated builders, to map selected response statuses to CoreEx results before normal deserialization and validation. `ValidatedHttpRequestBuilder<T>` integrates response validation with fluent request execution and automatic response disposal.
- *Enhancement:* Added `HttpResponseMessage.GetStringAsync()` and `ToStringResultAsync()` for raw response text, returning a null value for successful empty/204 responses; corresponding terminal methods are available on `HttpRequestBuilder`.
- *Enhancement:* Added host-builder `AddNamedHttpClient()` and its `AddHttpClient()` alias, sharing idempotency key handling, service discovery and standard resilience with `AddTypedHttpClient()`. A separate configuration-section overload supports augmenting SDK-owned named clients without replacing their registrations; base addresses may also be supplied by an existing registration or configuration callback.
- *Enhancement:* Added `IEfDb.SqlQuery<T>(SqlStatement, params object[])` for deferred, parameterized, composable EF queries over scalar or unmapped result types. Queries use the existing context and transaction, not the CoreEx Database command pipeline; CoreEx tenant and logical-delete filters are not automatically applied.
- *Enhancement:* Added `ReferenceDataOrchestrator.PrefetchAsync(IEnumerable<Type>)` for typed reference-data prefetch, validating all requested types before loading, deduplicating them and honoring configured parallelism. Name-based prefetch now also checks cancellation immediately.
- *Enhancement:* Added a predicate overload for validation `DependsOn`, allowing a rule to run only when its dependency is non-default, has no validation error, and satisfies an additional condition.
- *Enhancement:* Added expression-based `ValidationException.Create<TEntity>` factories and `RuntimeMetadata.GetJsonPath` for direct/nested property errors, including array/list indexes and string dictionary keys supplied as literals or captured locals. Resolves property JSON names from runtime metadata without executing entity access, using existing validator path notation; supports explicit serializer naming options and existing `LText` formatting.
- *Enhancement:* Added expression-based `Result.ValidationError<TEntity>` and `Result<T>.ValidationError<TEntity>` shorthand factories accepting a property expression, `LText` message, and optional exception configuration, using the same default JSON paths as `ValidationException.Create<TEntity>`.
- *Enhancement:* Expression-based validation exception and result factories now infer the standard invalid message when text is omitted/null, using `Validation.InvalidFormat` and friendly/localized property text resolved alongside the JSON path by `RuntimeMetadata.GetJsonPathAndText`.
- *Enhancement:* Updated the shipped AI guidance and reference-data documentation to explain implicit conversion from reference-data codes to concrete typed values, the annotated contract code-property pattern, and the separation of conversion from validation.
- *Enhancement:* Added OData-style free-text `$search` support to the `QueryArgs` querying pipeline: `QueryArgs.Search`; `QueryArgsConfig.WithSearch(Action<QuerySearchParser>)` with `QuerySearchMode` (`Keyword` executed by `QueryExtensions.Where` as a provider-agnostic predicate where every term must match a configured keyword field; `FullText`/`Semantic`/`Hybrid` are relevance-ranked and executed by the repository via `QueryArgsParseResult.IsRankedSearch`/`SearchResult.Text`, with `$orderby` rejected); `QuerySearchParserException`; `WithSearch` on `HttpRequestMessage`/`HttpRequestBuilder`; `QueryAttribute.SupportsSearch` (NSwag `$search` parameter); and a GraphQL-lite `search` argument on list roots. `$search` is rejected where not configured. The Products sample (and its MCP `search_products` tool) now uses `$search` to demonstrate.
- *Enhancement:* Added `DataResult<T>.Map` to transform mutation-result values while preserving `WasMutated`, including successful no-ops; simplified Shopping repository mapping and aligned usage guidance.
- *Behavior change:* Added a string-specific `Required()` validation overload that rejects null, empty and whitespace values with a `ValidationException`. Existing string call sites now reject empty/whitespace strings rather than only null.
- *Behavior change:* `JsonDefaults` now preserves dictionary keys by default (`DictionaryKeyPolicy = null`) instead of camel-casing/substituting them, preventing key identity changes and casing collisions during JSON round-trips. Property naming is unchanged; explicitly configured dictionary key policies remain supported. Dictionary validation/error paths preserve keys by default. Existing consumers relying on transformed keys must explicitly configure their previous policy.
- *Behavior change:* JSON Merge Patch now matches member names case-sensitively by default (`StringComparer.Ordinal`) to follow RFC 7396 and distinguish dictionary keys such as `P1` and `p1`. Clients must use exact serialized member names; explicitly configure `PropertyNameComparer = StringComparer.OrdinalIgnoreCase` only for previous non-standard compatibility.
- *Behavior change:* Preserve Shopping aggregate mutation metadata through repository mapping and gate Create/Update/Checkout mutation events with `WhereMutated`; align repository/service guidance and add successful-no-op publication regressions.
- *Behavior change:* Aligned Domain guidance and Shopping pricing/discount examples on business errors for aggregate/entity/value-object invariants, distinct from request validation. Pricing rejections (negative values, invalid/inactive unit of measure, quantity scale) now throw coded `BusinessException`; invalid/inactive discount application returns a coded business failure. Request validators retain field errors; shared argument/reference-data guards keep their existing exception semantics.
- *Maintenance:* Updated framework dependencies and corresponding `CoreEx.Template` dependencies, including Aspire 13.6.1, EF/.NET servicing packages and FusionCache 2.9.0. The SQL Server package now explicitly references `System.Security.Cryptography.Pkcs` 10.0.13; the Aspire template's MessagePack override is updated to 2.5.307.
- *Maintenance:* Pinned local development, CI and package publishing to the stable .NET SDK in `global.json`; updated `nuget-publish.ps1` to build before packing and remove matching package versions from the local NuGet cache by default.
- *Documentation:* Aligned application/API instructions, policy/service/adapter skills, and package/sample guidance on missing target resources (404) versus invalid request-body references (field-level 400), including query filters, expected downstream lookup outcomes, and deliberate endpoint semantics.
- *Fixed:* Named/typed HTTP client registration now binds standard resilience settings from the nested `Resilience` configuration section rather than the parent client section.
- *Fixed:* Common validators now preserve nullable null state instead of treating null as zero, retain caller labels/value formatting, and propagate normalized values through subsequent rules and additional validation callbacks. Unwrapped validation uses inner values for messages and nested entity paths, and writes normalization back to writable `Optional<T>` properties.
- *Fixed:* String, comparison, entity and common validation extension receivers now accept nullable reference inputs without nullable-annotation warnings, preserving existing fluent return types and runtime null behavior.
- *Fixed:* Exact-type internal casts now take their fast path before null/pattern checks, avoiding unnecessary value-type boxing in typed metadata reads. Common validation tracks null state separately from typed values rather than boxing values to represent null.
- *Fixed:* JSON Merge Patch now recursively processes object patches for new members and non-object targets, removing null-valued patch members rather than copying them literally. Removing a nonexistent member no longer reports a change.
- *Fixed:* Dictionary validation JSON paths now apply the effective serializer's `DictionaryKeyPolicy` to string keys for both key and value errors, matching serialized JSON and expression-based exception factories. Original keys remain unchanged in CLR paths and `GetDictionaryKey()`; JSON error paths preserve keys by default and use transformed casing only when a dictionary key policy is explicitly configured.
- *Fixed:* Shared cached property metadata lookups now consistently prefer static `IRuntimeMetadata` providers, including explicit implementations, with reflection as the fallback for other types. JSON path/friendly-label resolution respects custom/generated metadata for both root and nested types regardless of cache-population order. Explicit expression lookups separately cache reflected metadata for properties omitted by the static provider (including generated reference-data navigation properties), preserving validation support without changing contract equality/copy/clean property collections.
- *Fixed:* GraphQL-lite search parsing errors now preserve actionable per-property validation details in `extensions.messages["$search"]` while retaining the `SEARCH_PARSE_ERROR` code, including unsupported search, length/term limits and custom validation failures.
- *Fixed:* `CoreEx.UnitTesting` and the sample/template MockHost now explicitly reference MessagePack 2.5.307 so their transitive Aspire dependency cannot resolve the vulnerable 2.5.302 version; a central version entry alone does not pin transitive dependencies.
- *Fixed:* SQL Server and PostgreSQL unit-of-work root transactions now honor `DatabaseArgs.IsolationLevel`; nested invocations use savepoints and inherit the existing transaction's isolation level.
- *Fixed:* `HttpRequestMessage.WithQuery(QueryArgs)` (and therefore `HttpRequestBuilder.WithQuery(QueryArgs)`) previously ignored `IsIncludeText` and `IsIncludeInactive`; these are now sent as `$text=true` and `$inactive=true` respectively.

## v4.1.0
- *Enhancement:* Added `NamedDestinationProvider` (`AddNamedDestinationProvider()`); events are sent to the shared destination (topic), whereas commands are sent to a per-domain queue named `{Destination}-{domain}` so that only the addressed domain receives them. A `null` or empty command domain is self-addressed to the `IHostSettings.DomainName`.
- *Enhancement:* Added keyed `WithReceiver`/`WithSessionReceiver` and `WithKeyedSubscribedSubscriber` support to `AzureServiceBusReceiving` to enable multiple receivers (e.g. events topic and commands queue) within a single Subscribe host.
- *Enhancement:* Updated `CoreEx.Template` hosts to use the `NamedDestinationProvider` and a keyed subscriber by default, with the Service Bus topology now code-based in the generated `Test.Common` `ServiceBus` class.
- *Enhancement:* Added/extended end-to-end (`WithAspireTester`) Aspire testing capabilities within `CoreEx.UnitTesting`: `DistributedApplication` helpers to migrate SQL Server/PostgreSQL databases, clear the Redis cache and reset the Azure Service Bus emulator (queues, topics and subscriptions) from code; `AddEndpoints`, `AddHostedServiceSupport` and `DisableHttpCertificateValidation` AppHost extensions; and a WireMock-based `MockHost` to stub third-party HTTP dependencies. The `CoreEx.Template` `coreex-aspire` template now generates the AppHost, `MockHost` and `Test.Aspire` projects.
- *Enhancement:* Added `coreex-command-publish-e2e`, `coreex-command-subscribe-e2e` and `coreex-aspire` AI skills, with associated instructions, prompts and documentation.
- *Enhancement:* Added ReferenceDataOrchestrator.TryInvalidateAsync (best-effort, awaited, failure logged and swallowed) for post-commit cache eviction; the generated reference data write service now uses it so a cache outage cannot fail an already-committed mutation. Also, ReferenceDataHybridCache.RemoveAsync now serializes with in-flight loads to prevent re-caching stale data.
- *Enhancement:* Samples migrated to command queues; Aspire end-to-end tests now included in CI (`net10.0` only).
- *Enhancement:* Updated `CoreEx.CodeGen` to support mutability of reference data (side-effect was a rename of the previously generated `ReferenceDataService` (manually remove existing) to `ReferenceDataProvider`).
- *Enhancement:* Added `CosmosDbReferenceData` (Cosmos counterpart of `EfDbReferenceData`), `CosmosDbReferenceDataModelBase` and `CosmosDbContainerOptions.WithReferenceDataOutboxEvent`; `CoreEx.CodeGen` reference-data `mutability` now supports `repository: Cosmos` (unique `/typeDiscriminator` + `/code` key for duplicate-code detection).
- *Enhancement:* Added a scoped change tracker to `CoreEx.Cosmos` (`ICosmosDb.ChangeTracker`, `CosmosDbArgs.ClearChangeTrackerAfterGet`): repeat point gets are served from a per-scope snapshot cache, and `UpdateAsync` now pre-reads to copy back server-managed values (change-log `Created*`, `ttl`, unmapped extension data) and skip the replace when nothing changed. `CosmosDbModelBase` implements the new `CoreEx.Json.IExtensionData`.
- *Enhancement:* Added `CoreEx.Cosmos.Provisioning` (`CosmosDbProvisioner`, `CosmosDbConsole`, `CosmosDbProvisionArgs`, `CosmosDbContainerDefinition`): a reusable DbEx-style Drop/Create/Reset/Data console for Cosmos DB (dev/test; as per DbEx `Reset` does not implicitly create the database, and `Drop`/`Reset` prompt for confirmation unless `--accept-prompts` is specified), plus `CosmosDbBatch.ImportDiscriminatedBatchAsync` at container level and `MigrateCosmosDataAsync` in `CoreEx.UnitTesting` (first call `Create | ResetAndData`, then `ResetAndData`, as per `MigratePostgresDataAsync`). The seed-data `JsonDataReaderOptions` are overridable per container and per data file (`AddDataResource(..., dataOptions)` per file, `Container(..., dataOptions:)`/`ReferenceDataContainer(..., dataOptions:)` per container; the resource wins). The Customers sample now has a `Contoso.Customers.Database` project. As per DbEx, a `$`-prefixed seed key (container, or ref-data type group) is merged (upserted, re-runnable) rather than inserted, and a `^`-prefixed type group generates the `id` where not specified.
- *Enhancement:* Added `RuntimeMetadata.AreEqual` overload that excludes root-level properties from the comparison.
- *Enhancement:* Added `[NonNullable]` support for OpenAPI schemas to describe mandatory DTO properties that remain nullable in C#.
- *Enhancement:* Added fluent typed HTTP response validation and cached-result helpers for adapters; invalid successful dependency responses are surfaced as dependency failures rather than accepted or cached.
- *Enhancement:* Relational outbox publishers and relay hosts now share `CoreEx:Host:Outbox:PartitionSize` (default `4`, range `1`–`256`); configure it consistently in every writer and relay host. The former `CoreEx:Host:Services:OutboxRelay:PartitionSize` key is removed and causes relay startup to fail with a migration message. Keyless relational outbox events now use the stable `$none` sentinel rather than a random partition. Service Bus session hashing is independently configurable through `CoreEx:Host:ServiceBus:SessionIdPartitionSize`, with per-destination strategy and bucket overrides under `CoreEx:Host:ServiceBus:Destinations`.
- *Fix:* EF `Created*` audit columns are no longer generated as updatable/overwritten on update, and the default EF update mapping now excludes the change-log `Created*` and tenant properties (regenerate `*DbContext.g.cs` via `*.Database`).
- *Fixed:* `TimerHostedServiceBase` race where stopping (or `OneOffTrigger`/pause/resume) could `Cancel()` an already-disposed per-interval `CancellationTokenSource`, throwing `ObjectDisposedException` from `StopAsync` (intermittent host/test teardown failures). Also fixed abandoned interval-wait semaphore waiters accumulating per interval (unbounded growth) and swallowing subsequent wake-up signals (e.g. a resume could leave the service stuck paused).
- *Fixed:* `Extensions.IsCanceled()` now detects an `OperationCanceledException` wrapped in nested `AggregateException`s (as produced by multiple `Result.ThrowOnError()` boundaries); previously only a single level was detected, so cancellations could be misreported as failures.
- *Fixed:* `DatabaseOutboxRelayBase` now releases (cancels) a failed batch claim using a separate bounded token (new `CancelBatchTimeout`, default 30 seconds) rather than the already-cancelled lease-duration token, which previously left the claimed events locked until the database lease expired. A lease-duration timeout is now logged as a warning and treated as a partition-level failure (continuing to the next partition) rather than being rethrown as a cancellation that hosting services interpret as a stop request; a caller-requested cancellation still flows.
- *Fixed:* `CoreEx.Cosmos` `CosmosDbOutboxRelay` now self-recovers where the monitored and/or lease container is deleted and recreated whilst running (e.g. a provisioning `Reset`); previously the Change Feed Processor remained bound to the deleted containers, endlessly reporting lost leases (412/404) and never relaying another event until the host was restarted. A new `CosmosDbOutboxRelayOptions.RecoveryDelay` (default 5 seconds) controls the delay before/between recovery attempts.
- *Fixed:* Cosmos relay fresh leases explicitly read from the beginning, preventing existing outbox events from being skipped on first startup or container-reset recovery by the SDK's default "from now" behavior. Existing checkpoints take precedence; an explicitly configured `StartTime` remains supported.
- *Fixed:* Cosmos change-tracker snapshot publication is version-checked across model types, and immediate writes evict on completion as well as before mutation. Reads overlapping writes, invalidation, or a whole-tracker clear can no longer repopulate the cache with stale snapshots.
- *Fixed:* `CoreEx.Template` Relay host (and the Contoso sample relays) `OutboxRelay:LeaseDuration` increased from 5 to 30 seconds; the previous value was shorter than a single Azure Service Bus throttling back-off (~10 seconds), resulting in sends being cancelled mid-retry and batches repeatedly abandoned under load.
- *Fixed:* Products sample `MovementRepository` now adjusts inventory with atomic PostgreSQL statements (upsert for increases/adjustments, guarded `UPDATE` for decreases) rather than a tracked read-modify-write, so concurrent reservations for the same product no longer fail with a `DbUpdateConcurrencyException` (HTTP 500) and can never over-reserve.
- *Fixed:* Added `Extensions.IsCanceledBy(Exception, CancellationToken)` (nested-`AggregateException` aware) and applied it consistently so a caller-requested cancellation (shutdown/client disconnect) is no longer misclassified, swallowed or logged as an error: event subscriber/`SubscribedManager` error classification, Service Bus receiver (no longer converted per `UnhandledErrorHandling`, e.g. dead-lettered, on shutdown), `WebApi` (unhandled-exception conversion; a disconnect while reading the request body is no longer a 400), `WithTotalCountAsync` (no longer swallowed), and Error-level logging in `Database.GetConnectionAsync`, `CosmosDbInvoker`, `ReferenceDataOrchestrator` and `CosmosDbOutboxRelayProcessor`.
- *Breaking:* `IReferenceDataCache` has a new required `RemoveAsync(Type, CancellationToken)` member (any custom implementation must add it; `ReferenceDataHybridCache` already does), and `IIdentifierGenerator.AssignIdentifierAsync<TFor>` now constrains `TFor` to `class, IIdentifier`. Both are internal-plumbing extension points that are rarely implemented outside the framework, hence not treated as a major version.

## v4.0.0
- This is a **major** version release; a re-imagine / re-invention of the existing capabilities to enable a more modern, flexible and maintainable codebase.
  - This release contains **significant breaking changes** - there is **no** upgrade path from the previous `v3.x` versions; however, the core capabilities and patterns remain largely consistent.
  - A number of capabilities have been removed as they were not widely used, considered legacy/obsolete, or there are better alternatives available.
  - Not all existing capabilities have been re-implemented in this release; the intention is to (re-)add further capabilities in future releases as required.
- Special call out to key contributors: [israels](https://github.com/israels), [spruit-avanade](https://github.com/spruit-avanade) and [chullybun](https://github.com/chullybun).

## v3.* and earlier
- These versions are now considered **legacy** and are no longer maintained; there are no further updates planned for these versions, including bug fixes or security patches.
